# Run API verification — 2026-09-27

The authenticated runtime now exposes run creation/configuration, log upload, preflight,
ingest, stop and explicit reparse. Runs have private directories and independent indices.
Preflight executes the same Vector metadata/parser/schema transforms using stdin and no
Elasticsearch sink. Ingest requires a successful check of the current configuration and
input revision. Reparse checks input before deleting the previous index/checkpoint.
An uncertain index-creation result requires explicit reparse before another ingest.

Uploaded UTF-8 bytes are retained as `source-upload.bin` for the session lifetime.
The production input file uses exactly the preflight representation: remove the initial
UTF-8 BOM and CRLF carriage returns and terminate the final record with LF. Upload
invalidates the previous check before starting filesystem writes. `bytes` reports the
normalized input size. Data is stored on the ephemeral session disk, not “never stored.”

## Executed

- Local `npm test`: 67 passing, including manager state transitions, authentication,
  configuration/input revision fencing, malformed inputs, early process exit, failed
  index creation and upload normalization.
- Actual official Vector 0.58.0 on macOS: preflight valid/invalid/schema/compiler cases
  and file-source regression for BOM, CRLF and absent final newline: 2 tests passing.
  The latter runs the production source/transforms with a console sink; it does not
  establish disk-buffer or Elasticsearch delivery correctness.
- Independent read-only review found the preflight/file-source newline mismatch.
  A regression failed before normalization and passed after the fix.
